## Middleware

- [X] FND-004: `FireblocksErrorMapperMiddleware` is the outermost catch-all that maps unhandled exceptions to the Fireblocks-compatible `ErrorResponse {message, code}` JSON body with camelCase serialization. Mapping rules: `DbUpdateException` whose inner Postgres error is `UniqueViolation` on constraint `IX_Transactions_ExternalTxId` -> 409 / 1438 `External transaction id already exists`; `FireblocksApiException` -> its own StatusCode/ErrorCode/Message; `DuplicateExternalTxIdException` -> 409/1438; `ArgumentException`/`ArgumentNullException`/`InvalidOperationException` -> 400; `UnauthorizedAccessException` -> 401 `Unauthorized`; `KeyNotFoundException` -> 404 `Resource not found`; anything else -> 500 `An internal error occurred`. All exceptions are logged at Error level. Source: `Waterblocks.Api/Middleware/FireblocksErrorMapperMiddleware.cs:1-87`. Confidence: high.
- [X] FND-005: `HttpTrafficLoggingMiddleware` logs every HTTP exchange (excluding WebSocket upgrades, which log a `[websocket upgrade]` placeholder) with request method/path/query, status code, elapsed milliseconds, `TraceId`, request+response headers (with `Authorization`/`Cookie`/`Set-Cookie`/`X-API-Key` redacted as `[redacted]`), and request+response bodies (buffered via `EnableBuffering`/`MemoryStream`, truncated to 32 KiB with `...[truncated]`, only for text content types `application/json`, `application/problem+json`, `application/xml`, `application/x-www-form-urlencoded`, `text/*` or unset; binary bodies log `[body omitted for content type: ...]`, empty bodies log `[empty]`). Log level escalates by outcome: unhandled exception or 5xx -> `Error`, 4xx -> `Warning`, otherwise `Information`. The original response stream is restored and the buffer copied back so downstream clients still receive the body. Source: `Waterblocks.Api/Middleware/HttpTrafficLoggingMiddleware.cs:1-227`. Confidence: high.
