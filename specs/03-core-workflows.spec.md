## Auto-Transitions

- [X] TXN-023: The AutoTransitionService is an `IHostedService` background loop that automatically advances non-terminal transactions through their state machine for workspaces opted in via `AutoTransitionEnabled`. Each iteration loads non-deleted workspaces with `AutoTransitionEnabled = true` and, if any, fetches their non-terminal transactions (filtered by `TransactionStateMachine.NonTerminalStates`) ordered by `CreatedAt` ascending; when either list is empty the loop sleeps 5 seconds and retries. For each transaction it computes the next auto-state via `TransactionStateMachine.GetNextAutoState` and skips transitions the state machine deems invalid. Before transitioning into BROADCASTING a fresh hash is generated from the asset's BlockchainType when the transaction has no hash; if the asset is missing the transaction is skipped with a warning. When the next state is CONFIRMING, `Confirmations` is incremented by at least 1. When the next state is COMPLETED and `Confirmations` is zero it is bumped to 6, and balances are settled via `IBalanceService.CompleteTransactionAsync` (debit source, credit destination, release reservations). After all eligible transactions are transitioned and saved, the service builds a workspace-aware address-ownership lookup and emits `transactionUpserted` (with the admin DTO) to each transaction's workspace group, then emits `transactionsUpdated` and `vaultsUpdated` once per distinct workspace. The loop sleeps 1 second between iterations and logs and swallows exceptions to keep running. Source: `Waterblocks.Api/Services/AutoTransitionService.cs:10-145`. Confidence: high.
