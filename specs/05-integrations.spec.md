## SignalR (Realtime)

- [X] INT-WS-001: The AdminHub SignalR hub exposes a realtime channel for admin clients. On client connect every connection joins the admin-wide pending-transactions group and the admin-wide workspaces group; when the `workspaceId` query string parameter is present and non-blank, the connection also joins a SignalR group named after that workspace id. On disconnect the same connection is removed from each group it joined. This lets one connection receive both workspace-scoped updates for the selected workspace and admin-wide updates for shared shell UI. Source: planned changes in `Waterblocks.Api/Hubs/AdminHub.cs`. Confidence: medium.
- [X] INT-WS-002: The `transactionUpserted` SignalR event is broadcast to every workspace group that can observe the transaction because that workspace owns the source or destination address. Each recipient gets the workspace-scoped `AdminTransactionDto` produced for its own workspace id, so cross-workspace internal transfers appear live in both workspaces without a manual reload. Emitting an upsert also implicitly triggers the list-update fan-out (see INT-WS-003). The same event is also emitted by the AutoTransitionService for each transaction it advances, scoped to every workspace that participates in that transaction. Source: planned changes in `Waterblocks.Api/Services/AdminTransactionNotifier.cs`, `Waterblocks.Api/Services/AutoTransitionService.cs`. Confidence: medium.
- [X] INT-WS-003: The `transactionsUpdated` SignalR event is a payload-less notification sent to each affected workspace group to signal that the current workspace transaction list should be refreshed. It is emitted by `AdminTransactionNotifier.NotifyListsUpdatedAsync` (alongside `vaultsUpdated`) whenever a transaction upsert occurs, by `RealtimeNotifier.NotifyTransactionsUpdatedAsync(workspaceId)` (no-op when `workspaceId` is null/blank), and by the AutoTransitionService for each distinct workspace whose transactions advanced in a tick. Source: planned changes in `Waterblocks.Api/Services/AdminTransactionNotifier.cs`, `Waterblocks.Api/Services/RealtimeNotifier.cs`, `Waterblocks.Api/Services/AutoTransitionService.cs`. Confidence: medium.
- [X] INT-WS-004: The `vaultUpserted` SignalR event is broadcast to the workspace group whenever a vault is created, updated, or a wallet is added to it via the admin API. The payload is the full `AdminVaultDto` (including nested wallets and addresses, mapped after reloading the vault with wallets+addresses). It is emitted by `AdminVaultsController.CreateVault` and `UpdateVault`, and by `AdminVaultService.CreateWalletAsync` after a wallet is created or augmented. Source: `Waterblocks.Api/Controllers/Admin/AdminVaultsController.cs:113-122, 153-160`, `Waterblocks.Api/Services/AdminVaultService.cs:143-150`. Confidence: high.
- [X] INT-WS-005: The `vaultsUpdated` SignalR event is a payload-less notification sent to each affected workspace group to signal that the vaults list should be refreshed. It is emitted by the admin vaults controller after create/update/delete/archive/unarchive (always paired with `vaultUpserted` on create/update), by `AdminVaultService.CreateWalletAsync` after wallet creation, by `RealtimeNotifier.NotifyVaultsUpdatedAsync(workspaceId)` (no-op when `workspaceId` is null/blank), by `AdminTransactionNotifier.NotifyListsUpdatedAsync` (paired with `transactionsUpdated` on every transaction upsert for every workspace touched by that transaction), and by the AutoTransitionService for each distinct workspace whose transactions advanced in a tick. Source: planned changes in `Waterblocks.Api/Controllers/Admin/AdminVaultsController.cs`, `Waterblocks.Api/Services/AdminVaultService.cs`, `Waterblocks.Api/Services/RealtimeNotifier.cs`, `Waterblocks.Api/Services/AdminTransactionNotifier.cs`, `Waterblocks.Api/Services/AutoTransitionService.cs`. Confidence: medium.
- [X] INT-WS-006: The frontend `useRealtimeUpdates(workspaceId)` hook connects to `/hubs/admin?workspaceId=...` using `@microsoft/signalr` with `withAutomaticReconnect` and `LogLevel.Warning`, returns a status string (`connecting`/`connected`/`reconnecting`/`disconnected`), and keeps the current workspace UI live by upserting `transactionUpserted` payloads into the React Query caches and invalidating the workspace-scoped paged transaction list, invalidating the corresponding workspace-scoped lists on `transactionsUpdated`/`vaultsUpdated`, and invalidating the global `['workspaces']` query on the admin-wide `workspacesUpdated` event. When the underlying connection closes (and the component is still mounted) it schedules a manual reconnect with exponential backoff (`min(30s, 1s * 2^attempt)`), resets the attempt counter on a successful start, and tears down the connection on workspace change/unmount. With no `workspaceId` the hook reports `disconnected` and skips the connection entirely. Source: planned changes in `waterblocks-admin/src/hooks/useRealtimeUpdates.ts`, `waterblocks-admin/src/App.tsx`. Confidence: medium.
- [X] INT-WS-007: The admin realtime channel also exposes an admin-wide `pendingTransactionsUpdated` SignalR event for header consumers that are not scoped to a single workspace. The event is emitted whenever a transaction is created, updated, or transitions in a way that can change the all-workspaces non-terminal pending summary (including entering or leaving `TransactionStateMachine.NonTerminalStates`), so the pending-transactions header can refresh without requiring the user to switch workspaces. Source: planned changes in `Waterblocks.Api/Hubs/AdminHub.cs`, `Waterblocks.Api/Services/AdminTransactionNotifier.cs`, `Waterblocks.Api/Services/AutoTransitionService.cs`. Confidence: medium.
- [X] INT-WS-008: The frontend subscribes to the admin-wide pending-transactions realtime event separately from the workspace-scoped transaction/vault updates and uses it to invalidate or refetch the all-workspaces pending-transactions summary query while preserving the existing selected-workspace caches and realtime status indicator. Source: planned changes in `waterblocks-admin/src/hooks/useRealtimeUpdates.ts`, `waterblocks-admin/src/App.tsx`, `waterblocks-admin/src/api/queries.ts`. Confidence: medium.
- [X] INT-WS-009: The admin realtime channel also exposes an admin-wide `workspacesUpdated` SignalR event for shell and `/workspaces` consumers. The event is emitted whenever the visible workspace list changes through `POST /admin/workspaces`, `DELETE /admin/workspaces/{id}`, or `POST /admin/workspaces/archive-all`, so the workspace selector and workspaces page refresh without requiring a manual reload. Source: planned changes in `Waterblocks.Api/Hubs/AdminHub.cs`, `Waterblocks.Api/Controllers/Admin/AdminWorkspacesController.cs`. Confidence: medium.
