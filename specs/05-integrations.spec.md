## SignalR (Realtime)

- [X] INT-WS-001: The AdminHub SignalR hub exposes a realtime channel for admin clients. On client connect the hub reads the `workspaceId` query string parameter from the HTTP request and, when present and non-blank, adds the connection to a SignalR group named after the workspace id; on disconnect the same connection is removed from that group. Connections without a `workspaceId` query parameter join no group and therefore receive no workspace-scoped events. Source: `Waterblocks.Api/Hubs/AdminHub.cs:5-28`. Confidence: high.
- [X] INT-WS-002: The `transactionUpserted` SignalR event is broadcast to the workspace group whenever a transaction is created or mutated through the admin notifier. The payload is the workspace-scoped `AdminTransactionDto` produced by `IAdminTransactionMapper.MapAsync(transaction, workspaceId)`. Emitting an upsert also implicitly triggers the list-update fan-out (see INT-WS-003). The same event is also emitted by the AutoTransitionService for each transaction it advances, scoped to that transaction's workspace group. Source: `Waterblocks.Api/Services/AdminTransactionNotifier.cs:25-31`, `Waterblocks.Api/Services/AutoTransitionService.cs:119-130`. Confidence: high.
- [X] INT-WS-003: The `transactionsUpdated` SignalR event is a payload-less notification sent to a workspace group to signal that the transactions list should be refreshed. It is emitted by `AdminTransactionNotifier.NotifyListsUpdatedAsync` (alongside `vaultsUpdated`) whenever a transaction upsert occurs, by `RealtimeNotifier.NotifyTransactionsUpdatedAsync(workspaceId)` (no-op when `workspaceId` is null/blank), and by the AutoTransitionService for each distinct workspace whose transactions advanced in a tick. Source: `Waterblocks.Api/Services/AdminTransactionNotifier.cs:33-37`, `Waterblocks.Api/Services/RealtimeNotifier.cs:21-29`, `Waterblocks.Api/Services/AutoTransitionService.cs:131-135`. Confidence: high.
- [X] INT-WS-004: The `vaultUpserted` SignalR event is broadcast to the workspace group whenever a vault is created, updated, or a wallet is added to it via the admin API. The payload is the full `AdminVaultDto` (including nested wallets and addresses, mapped after reloading the vault with wallets+addresses). It is emitted by `AdminVaultsController.CreateVault` and `UpdateVault`, and by `AdminVaultService.CreateWalletAsync` after a wallet is created or augmented. Source: `Waterblocks.Api/Controllers/Admin/AdminVaultsController.cs:113-122, 153-160`, `Waterblocks.Api/Services/AdminVaultService.cs:143-150`. Confidence: high.
- [X] INT-WS-005: The `vaultsUpdated` SignalR event is a payload-less notification sent to a workspace group to signal that the vaults list should be refreshed. It is emitted by the admin vaults controller after create/update/delete/archive/unarchive (always paired with `vaultUpserted` on create/update), by `AdminVaultService.CreateWalletAsync` after wallet creation, by `RealtimeNotifier.NotifyVaultsUpdatedAsync(workspaceId)` (no-op when `workspaceId` is null/blank), by `AdminTransactionNotifier.NotifyListsUpdatedAsync` (paired with `transactionsUpdated` on every transaction upsert), and by the AutoTransitionService for each distinct workspace whose transactions advanced in a tick. Source: `Waterblocks.Api/Controllers/Admin/AdminVaultsController.cs:121, 159, 186, 220`, `Waterblocks.Api/Services/AdminVaultService.cs:150`, `Waterblocks.Api/Services/RealtimeNotifier.cs:31-39`, `Waterblocks.Api/Services/AdminTransactionNotifier.cs:36`, `Waterblocks.Api/Services/AutoTransitionService.cs:134`. Confidence: high.
- [X] INT-WS-006: The frontend `useRealtimeUpdates(workspaceId)` hook connects to `/hubs/admin?workspaceId=...` using `@microsoft/signalr` with `withAutomaticReconnect` and `LogLevel.Warning`, returns a status string (`connecting`/`connected`/`reconnecting`/`disconnected`), and on receiving `transactionUpserted` upserts the transaction in the React Query caches `['transactions', workspaceId]` and `['transaction', workspaceId, id]` plus invalidates `['transactionsPaged', workspaceId]`; on `vaultUpserted` upserts into `['vaults', workspaceId]` and `['vault', workspaceId, id]`; on `transactionsUpdated`/`vaultsUpdated` invalidates the corresponding workspace-scoped lists. When the underlying connection closes (and the component is still mounted) it schedules a manual reconnect with exponential backoff (`min(30s, 1s * 2^attempt)`), resets the attempt counter on a successful start, and tears down the connection on workspace change/unmount. With no `workspaceId` the hook reports `disconnected` and skips the connection entirely. Source: `waterblocks-admin/src/hooks/useRealtimeUpdates.ts:1-112`. Confidence: high.
