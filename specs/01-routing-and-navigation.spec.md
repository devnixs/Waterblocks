## Routes

- [X] UI-TXN-001: The admin UI registers `/`, `/transactions`, and `/transactions/:transactionId` to render `TransactionsPage`. The list routes continue to show workspace transactions (paginated via `useTransactionsPaged`), support asset/id/hash filters, a create-transaction form, bulk selection/actions, keyboard navigation, and a detail panel with state transitions. The direct transaction route opens the referenced workspace-scoped transaction detail view immediately so shell links can land on a transaction without manual filtering or row selection. Source: planned changes in `waterblocks-admin/src/App.tsx`, `waterblocks-admin/src/pages/TransactionsPage.tsx`. Confidence: medium.
- [X] UI-VAULT-001: The admin UI registers `/vaults` to render `VaultsPage`, which lists workspace vaults (`useVaults`), can toggle archived view, supports a create-vault form, opens a detail panel with wallet creation/rename/archive/unarchive, and honors `?vaultId=`/`?vaultName=` query parameters for auto-selection. Source: `waterblocks-admin/src/App.tsx:186`, `waterblocks-admin/src/pages/VaultsPage.tsx:20-192`. Confidence: high.
- [X] UI-WS-001: The admin UI registers `/workspaces` to render `WorkspacesPage`, which lists all workspaces (`useWorkspaces`), creates new workspaces with an `autoTransitionEnabled` toggle, archives them via `useDeleteWorkspace`, displays each workspace's API keys, and stays in sync with realtime workspace-list websocket updates so newly created or archived workspaces appear or disappear without a manual page reload. Source: planned changes in `waterblocks-admin/src/App.tsx`, `waterblocks-admin/src/pages/WorkspacesPage.tsx`, `waterblocks-admin/src/hooks/useRealtimeUpdates.ts`. Confidence: medium.
- [X] UI-WS-002: When the runtime config flag `archiveAllWorkspacesEnabled` is true, `WorkspacesPage` renders a top-of-page danger action named `Archive all workspaces` above the workspace list. Triggering it requires confirmation, archives every non-deleted workspace except the workspace named `Default`, refreshes the list, and surfaces success or failure through the page toast system. When the flag is false or absent, the bulk action is not shown. Source: `waterblocks-admin/src/pages/WorkspacesPage.tsx`, `waterblocks-admin/src/config/runtimeConfig.ts`, `waterblocks-admin/src/api/adminClient.ts`, `waterblocks-admin/src/api/queries.ts`. Confidence: high.
- [X] UI-ASSET-001: The admin UI registers `/assets` to render `AssetsPage`, which lists assets (`useAdminAssets`), creates assets with full metadata (assetId/name/symbol/decimals/type/blockchainType/contract/native/baseFee/feeAssetId/isCaseSensitive/isActive), and edits/deactivates via an `AssetEditPanel`. Source: `waterblocks-admin/src/App.tsx:188`, `waterblocks-admin/src/pages/AssetsPage.tsx:24-310`. Confidence: high.

## App Shell

- [X] UI-SHELL-001: The app shell renders a header with logo, build commit hash (from `VITE_APP_COMMIT_HASH`), nav links to Transactions/Vaults/Workspaces/Assets (active class based on `location.pathname`), a workspace selector `<select>` that persists `workspaceId` to `localStorage`, invalidates all queries on change, and refreshes live when the global workspace list changes over websocket, a `?` help button, an Auto-transition toggle (calls `useSetAutoTransitions`, disabled while pending or without workspace), a realtime status indicator driven by `useRealtimeUpdates`, and a user info block with current email and Logout button. Source: planned changes in `waterblocks-admin/src/App.tsx`, `waterblocks-admin/src/hooks/useRealtimeUpdates.ts`. Confidence: medium.
- [X] UI-SHELL-002: The app shell auto-selects the first workspace when none is stored, and falls back to the first workspace if the stored `workspaceId` no longer exists in the workspace list. Source: `waterblocks-admin/src/App.tsx:57-78`. Confidence: high.
- [X] UI-SHELL-003: The app shell gates the entire UI behind `LoginGate` (rendered when `useCurrentUser` reports no email) and only mounts the routed shell once an email is captured. Source: `waterblocks-admin/src/App.tsx:88-90`. Confidence: high.
- [X] UI-SHELL-004: The app shell binds global keyboard shortcuts via `useKeyboardShortcuts`: `1`/`2`/`3`/`4` navigate to Transactions/Vaults/Workspaces/Assets, and `?` opens the keyboard shortcuts dialog. Source: `waterblocks-admin/src/App.tsx:80-86`. Confidence: high.
- [X] UI-SHELL-005: The `KeyboardShortcutsDialog` (Radix Dialog) documents Global shortcuts (1-4 nav, `/` focus, `Esc` close, `?` help), List navigation (`j`/`k`/arrows, `Enter`, `Space`, `Ctrl/Cmd+A`/`D`), and Transaction Detail Panel shortcuts (`a`/`s`/`c`/`f`/`x` actions, `Ctrl/Cmd+C` copy), and is opened from the shell's `?` button or `?` key. Source: `waterblocks-admin/src/components/KeyboardShortcutsDialog.tsx:8-95`. Confidence: high.
- [X] UI-SHELL-006: The `useKeyboardShortcuts` hook attaches a `window` keydown listener that matches key, ctrl/meta, and shift modifiers (treating Ctrl and Cmd as equivalent), suppresses shortcuts while focus is in INPUT/TEXTAREA/contentEditable (except Escape), calls `preventDefault()` before invoking the handler, and short-circuits after the first match; the entire binding can be toggled via the `enabled` flag. Source: `waterblocks-admin/src/hooks/useKeyboardShortcuts.ts:12-45`. Confidence: high.
- [X] UI-SHELL-007: The app shell renders a header item labeled `{count} pending transactions`, where `count` is the current number of transactions across all workspaces whose states are in the non-terminal set (`SUBMITTED`, `PENDING_SIGNATURE`, `PENDING_AUTHORIZATION`, `QUEUED`, `BROADCASTING`, `CONFIRMING`). The count is not limited to the currently selected workspace and refreshes in realtime from websocket-driven updates. Source: planned changes in `waterblocks-admin/src/App.tsx`, `waterblocks-admin/src/api/adminClient.ts`, `waterblocks-admin/src/api/queries.ts`. Confidence: medium.
- [X] UI-SHELL-008: Clicking the pending-transactions header item toggles a small scrollable dropdown rendered as a styled `<div>` overlay, not a native `<select>`. The dropdown lists the current non-terminal transactions newest first and each row shows amount, asset, status, source workspace, source address name, source address, destination workspace, destination address name, and destination address. Clicking a row closes the dropdown, updates the active workspace selection to the row's workspace-scoped context, and navigates to `/transactions/:transactionId` for that transaction. Source: planned changes in `waterblocks-admin/src/App.tsx`, `waterblocks-admin/src/App.css`, `waterblocks-admin/src/pages/TransactionsPage.tsx`. Confidence: medium.
