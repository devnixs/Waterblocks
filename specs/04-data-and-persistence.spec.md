## Entities

- [X] DATA-001: The `Workspace` entity is the top-level multi-tenant boundary. It is keyed by a string `Id` (GUID-string, max 50) with a required `Name` (max 255), an `AutoTransitionEnabled` boolean opting the workspace into background state-machine advancement, `CreatedAt`/`UpdatedAt` timestamps, and a soft-delete pair `IsDeleted` + nullable `DeletedAt`. Workspaces own collections of `VaultAccount`, `Transaction`, and `ApiKey`. Source: `Waterblocks.Api/Models/Workspace.cs`. Confidence: high.
- [X] DATA-002: The `ApiKey` entity issues credentials for a workspace. It is keyed by a string `Id` (GUID-string, max 50) and carries required `Name` (max 255), opaque `Key` value (max 255), and `WorkspaceId` (max 50) foreign key with a navigation to `Workspace`. `CreatedAt`/`UpdatedAt` are stamped on creation. Source: `Waterblocks.Api/Models/ApiKey.cs`. Confidence: high.
- [X] DATA-003: The `VaultAccount` entity represents a tenant-scoped container of crypto holdings. It is keyed by a string `Id` (GUID-string) with required `Name` (max 255) and `WorkspaceId` (max 50, FK to `Workspace`), plus UI/customer-control fields `HiddenOnUI` (bool, default false), `CustomerRefId` (max 255, optional), and `AutoFuel` (bool, default false). It supports soft-archive via `IsArchived` + nullable `ArchivedAt`, and stamps `CreatedAt`/`UpdatedAt`. A vault owns a collection of `Wallet`. Source: `Waterblocks.Api/Models/VaultAccount.cs`. Confidence: high.
- [X] DATA-004: The `Wallet` entity is the per-asset balance container inside a `VaultAccount`. It uses an integer surrogate `Id` (so multiple wallets per vault+asset are allowed), required `VaultAccountId` (max 50, FK) and `AssetId` (max 50), and a `Type` discriminator (max 50, defaulting to "Permanent"). Balance state is split across decimal(36,18) columns `Balance`, `LockedAmount`, `Pending`, `Frozen`, `Staked` (all default 0). Optional `BlockHeight` and `BlockHash` strings (max 100) carry simulated chain metadata. `CreatedAt`/`UpdatedAt` are stamped. A wallet owns a collection of `Address`. Source: `Waterblocks.Api/Models/Wallet.cs`. Confidence: high.
- [X] DATA-005: The `Address` entity stores one deposit/receive address belonging to a `Wallet`. It uses an integer surrogate `Id` with a required `AddressValue` (max 500) and an integer `WalletId` foreign key. Optional descriptive fields include `Tag` (memo, max 100), `Type` (max 50), `Description` (max 500), `CustomerRefId` (max 100), `AddressFormat` (max 20, e.g. SEGWIT/LEGACY/BASE/PAYMENT), `LegacyAddress` and `EnterpriseAddress` (max 500), and a nullable `Bip44AddressIndex` integer for HD-derivation order. `CreatedAt` is stamped on creation. Source: `Waterblocks.Api/Models/Address.cs`. Confidence: high.
- [X] DATA-006: The `Asset` entity is the catalogue row describing a supported crypto asset. It is keyed by a string `AssetId` (max 50, the public identifier) with required `Name` (max 100) and `Symbol` (max 64), `Decimals` (default 18), optional `Type` (max 50), and a `BlockchainType` enum (`AccountBased`, `AddressBased`, `MemoBased`) controlling address/memo handling. Fee configuration lives in `BaseFee` (decimal(36,18), default 0) and optional `FeeAssetId` (max 50) plus `NativeAsset` (max 50), with helper `GetFeeAssetId()` falling back FeeAssetId -> NativeAsset -> self and `HasSeparateFeeAsset()` detecting token-style fee payment. Address-matching is controlled by `IsCaseSensitive` (default true). Soft-deactivation via `IsActive` (default true). `CreatedAt` is stamped. Source: `Waterblocks.Api/Models/Asset.cs`. Confidence: high.
- [X] DATA-007: The `Transaction` entity records one transfer attempt and the full state-machine history. It is keyed by a string `Id` (GUID-string, max 100), references the originating `VaultAccountId` (max 50, FK), and stores an optional legacy `WorkspaceId` (kept for back-compat; runtime workspace scoping is by address ownership, not this column). It carries `AssetId`, `SourceAddress` and `DestinationAddress` (max 500), optional `DestinationTag` (max 100), `Amount` and `RequestedAmount` (decimal(36,18); the latter preserves the original request when gross-amount fee deduction is applied), `State` (`TransactionState` enum, default SUBMITTED), optional `SubStatus`/`Hash`/`FailureReason`/`Note`/`ExternalTxId`/`CustomerRefId`/`InitiatedBy`/`FeeCurrency`/`ReplacedByTxId`, fee fields `Fee`/`NetworkFee`/`ServiceFee` (decimal(36,18)), a `Confirmations` counter, an `Operation` string (default "TRANSFER"), an `IsFrozen` flag, a `TreatAsGrossAmount` flag (when true `Amount = RequestedAmount - NetworkFee`), and `CreatedAt`/`UpdatedAt`. Behaviour methods `TransitionTo(newState)` validates the transition via the state machine before mutating `State` and `UpdatedAt`; `Freeze()`/`Unfreeze()` toggle `IsFrozen` and refresh `UpdatedAt`, rejecting terminal-state transactions. Source: `Waterblocks.Api/Models/Transaction.cs`. Confidence: high.
- [X] DATA-008: The `TransactionState` enum enumerates the 11 lifecycle states of a transaction: `SUBMITTED`, `PENDING_SIGNATURE`, `PENDING_AUTHORIZATION`, `QUEUED`, `BROADCASTING`, `CONFIRMING`, `COMPLETED`, `FAILED`, `REJECTED`, `CANCELLED`, `TIMEOUT`. Extension methods `IsTerminal`, `CanTransitionTo`, and `ValidateTransition` delegate to the shared `TransactionStateMachine.Instance` so transition rules are centralized. Source: `Waterblocks.Api/Models/TransactionState.cs`. Confidence: high.
- [X] DATA-009: The `AdminSetting` entity is a global key/value store for administrative configuration. It is keyed by `Key` (max 100) with a `Value` string (max 2000) and an `UpdatedAt` timestamp. It is not workspace-scoped. Source: `Waterblocks.Api/Models/AdminSetting.cs`. Confidence: high.

## Seed Data

- [X] DATA-010: At startup `SeedData.SeedDatabase` is called from `Program.cs`: it creates a DI scope, applies pending EF Core migrations (`db.Database.Migrate()`), invokes `SeedHelpers.SeedWorkspaces` (idempotent default-workspace + admin api-key bootstrap), then loads the asset catalogue from `all_assets.json` next to the binary (warns and continues if the file is missing). Source: `Waterblocks.Api/Infrastructure/SeedData.cs:7-26`. Confidence: high.
- [X] DATA-011: Asset seeding deserialises `all_assets.json` into `AssetSeed` records (`Description`/`Name`/`Code`/`Symbol`/`API_ID`/`Decimals`/`Type`/`BlockchainType`/`ContractAddress`/`NativeAsset`/`BaseFee`/`FuelAssetId`/`IsCaseSensitive`); picks the asset symbol as `Symbol ?? API_ID ?? Code` (skipping rows where symbol is missing or `N/A`), de-dupes against existing `Symbol`/`AssetId` (case-insensitive), parses `BlockchainType` enum (defaults to `AccountBased`), and inserts `Asset` rows with `IsActive=true`, `CreatedAt=UtcNow`, defaulting `BaseFee` to 0. Case-sensitivity is inferred when not supplied: `false` if `ContractAddress` starts with `0x` or `NativeAsset` is one of `ETH`/`MATIC_POLYGON`/`BNB_BSC`/`AVAX_C`/`BASECHAIN_ETH` (EVM family), else `true`. `FireblocksAssetSeed` is a separate DTO (Id/Name/Type/ContractAddress/Decimals/NativeAsset) reserved for the Fireblocks supported-assets seed shape but not used by the active seeder. Source: `Waterblocks.Api/Infrastructure/SeedData.cs:27-117`, `Waterblocks.Api/Infrastructure/AssetSeed.cs:1-22`, `Waterblocks.Api/Infrastructure/FireblocksAssetSeed.cs:1-12`. Confidence: high.
